設定案（提案書）の作り方

ヒアリングの前に、広告の設定内容を1枚にまとめた「設定案」を作ります。お客様には前日までにリンクを送り、ヒアリングの電話では設定案を一緒に見ながら確認します。

1
全体像 設定案とは

YouTube広告をどう配信するかを、お客様向けに1枚のページにまとめたものです。表紙のタイトルは全店舗共通で「YouTube広告 運用設定案のご案内」。デザインは決まった形があり、店舗ごとに変えるのは中身だけです。

2
導入 設定案スキルを導入する（最初に1回だけ）

設定案は、Claude Codeに手順書と作成用のファイル一式（proposal フォルダ）を読み込ませて作ります。一式は社内の非公開リポジトリ Case-management-ads の中にあります。Mac向けの手順です（Windowsの場合は上長に相談してください）。見出しを押すと手順が開きます。AIに任せることもできます。

🤖 AIに任せる場合（Claude Codeに貼る指示文）

Case-management-ads のフォルダで Claude Code を開き、下の文をそのまま貼って送ります。AIが①〜⑦を順に確認・実行し、Chromeの終了やコピーなど大事な操作の前には確認してくれます。Clone（①）・GitHub への招待・Aloom MCP のダウンロード（⑦）は自分で行います。

設定案スキル（Case-management-ads の proposal フォルダ）を使えるように、この Mac の導入をしてください。 各手順の前に何をするか一言伝えてください。Chromeの終了・ファイルのコピー・設定の上書きなど、元に戻しにくい操作は実行前に必ず私に確認してください。 1. Case-management-ads のフォルダを探す（例：~/Documents/GitHub/Case-management-ads）。見つからなければ止めて、GitHub Desktop で runbird-inc/Case-management-ads を Clone するよう私に伝える。見つかったら git pull で最新にする。 2. Case-management-ads/proposal/ に ads-proposal.md・input-template.md・build_onesheet.py・build_copy_page.py・assets/・map-tools/・example/ がそろっているか確認する。足りなければ止めて報告する。proposal フォルダの中身は社内用なので、ほかの場所へのコピーや外部へのアップロードはしない。 3. python3 --version で Python 3 が使えるか確認する。使えなければ xcode-select --install を案内する。 4. ~/chrome-automation があるか確認する。なければ、Chrome をすべて終了してよいか私に確認してから、~/Library/Application Support/Google/Chrome/ を ~/chrome-automation/ にコピーする。 5. curl -s http://127.0.0.1:9222/json/version で、ポート9222の Chrome が起動しているか確認する。起動していなければ、次のコマンドで起動する（open で起動し、Claude Code の終了と一緒に Chrome が閉じないようにする）。起動直後は応答しないことがあるので、数秒おきに数回確認する。 open -na "Google Chrome" --args --remote-debugging-port=9222 --user-data-dir=$HOME/chrome-automation 起動したら、プロフィールを選ぶ画面が出ていないか確認する。出ていたら、ふだん使う自分のアカウントを選び、Googleなどのページを1つ開いておくよう私に伝え、開いたと返事があるまで待つ。 6. claude mcp list で puppeteer が入っているか確認する。必要なのは puppeteer-mcp-server（puppeteer_connect_active_tab が使えるもの）。なければ Case-management-ads のフォルダで claude mcp add puppeteer -- npx -y puppeteer-mcp-server を実行する。同じ名前で別の puppeteer が入っている場合は、置き換えてよいか私に確認する。追加したら、Claude Code の再起動が必要だと私に伝える。 7. claude mcp list で aloom（Aloomへの保存に使う）が入っているか確認する。なければ、配布された Aloom MCP をダウンロード済みか私に聞き、ダウンロード済みなら配布物に入っている手順どおりに追加する（手順が分からないときは止めて報告する）。追加したら、Claude Code の再起動が必要だと私に伝える。 8. 最後に、1〜7の結果を ✅／❌ の一覧で報告する。再起動が必要なときは「再起動後に『Puppeteerでポート9222のChromeに接続して』と送ってください。Chromeで普通のページが1つ開いていないと接続できません」と添える。
① Case-management-ads を手元に用意する
  • GitHub Desktop の「File → Clone repository」で runbird-inc/Case-management-ads を選び、Clone する
  • 一覧に出てこないときは、GitHubに招待されていない。上長に招待を依頼する
  • すでに手元にある場合は「Fetch origin」→「Pull origin」で最新にする
② proposal フォルダがあるか確認する

Case-management-ads の中に proposal フォルダがあり、次のファイルが入っていればOKです。

ファイル役割
ads-proposal.md手順書（Claudeが読む）
input-template.md入力テンプレートと指示の例文
build_onesheet.py設定案のページを作るプログラム
build_copy_page.py設定案の文章をメール・LINEに貼るためのコピー用ページを作るプログラム
assets/RUNBIRDのロゴ
map-tools/地図撮影の下地ページ
example/完成見本
proposal フォルダはお客様のURLなどを含む社内用です。研修サイトや社外のフォルダにコピーしない。フォルダが見当たらないときは上長に確認する。
③ Python が使えるか確認する

ターミナルで次を実行し、「Python 3.〇〇」と表示されればOKです。開発者ツールのインストールを求められたら「インストール」を押し、終わったらもう一度実行します。

python3 --version
④ 地図撮影用のChromeを用意する

地図は、Claudeがポート9222で起動したChromeを操作して撮ります。最初に、ふだんのChromeの設定（ログイン状態など）をコピーします。Chromeをすべて終了してからターミナルで実行します（初回のみ）。

cp -r ~/Library/Application\ Support/Google/Chrome/ ~/chrome-automation/

設定案を作るときは、毎回次のコマンドでChromeを起動します。

open -na "Google Chrome" --args --remote-debugging-port=9222 --user-data-dir=$HOME/chrome-automation

プロフィールを選ぶ画面が出たら、ふだん使う自分のアカウントを選びます。Claudeはページが1つも開いていないChromeにはつながらないので、Googleなどのページを1つ開いておきます。

Automator の「アプリケーション」で「シェルスクリプトを実行」に上の起動コマンドを貼って保存すると、ダブルクリックで起動できるアイコンになる。
⑤ Claude CodeにPuppeteer（ブラウザ操作）を追加する

ターミナルで Case-management-ads のフォルダに移動してから、次を実行します。

claude mcp add puppeteer -- npx -y puppeteer-mcp-server

Claude Codeを起動し直して /mcp と入力し、一覧に puppeteer が出ていればOKです。

⑥ つながるか試す

④のChromeを起動し、ページを1つ開いた状態で、Claude Codeに次のように送ります。接続できたと返ってくれば導入完了です。

Puppeteerでポート9222のChromeに接続して（puppeteer_connect_active_tab）
⑦ Aloom MCP を入れる（お客様へ送るときに使う）

お客様に送る設定案はAloomに保存します。Claudeに「〇〇の設定案をAloomに保存して」と頼めるように、配布される Aloom MCP を入れておきます。

  • 配布された Aloom MCP をダウンロードする
  • 配布物に入っている手順どおりに Claude Code へ追加する
  • Claude Code を起動し直して /mcp と入力し、一覧に aloom が出ていればOK
①〜⑦でつまずいたら、画面のスクリーンショットを付けて上長に相談する。自己流で設定を変えない。
3
入力 内容を入力する

入力のしかたは2つあります。

  • A. 入力フォーム（おすすめ）：項目ごとに入力して「保存する」を押す。保存した店舗は一覧に残り、あとから直せる。フォームのリンクは上長から共有してもらう
  • B. チャットに直接貼る：入力テンプレート（input-template.md）を埋めて、指示文の下に貼る
入力のきまり
  • 【設定のポイント】を付けた文は、設定案で青灰色の囲みになる。書いた文がそのまま載る
  • 【ご確認ください】を付けた項目には黄色の注意表示が付く。お客様に確認してほしい項目にだけ付ける（ヒアリングで聞く項目の目印になる）
  • 住所は番地まで書く。地図はその住所を中心に作られる。住所がなく駅名だけなら駅が中心になる
  • 言い切らずに「〜を検討しております」と書く。「反応率の高い時間帯」のような根拠が要る表現は、根拠があるときだけ使う
インスタ・Googleマップ・納品動画を見て、来客層やお店の強みからターゲットとキーワードの案を考える。迷う項目には【ご確認ください】を付けて、ヒアリングで決めればよい。
4
作成 Claudeに作ってもらう

Case-management-ads のフォルダでClaude Codeを開き、手順書（ads-proposal.md）を読ませてから指示します。フォームで保存した場合は、店舗名を入れた1行だけで作れます。

proposal/ads-proposal.md を読んで、〇〇サロンの設定案作って

「提案書作りたい」と送ると、フォームに保存済みの店舗の一覧から選べます。地図の撮影・ページの作成・公開まで、Claudeが手順書どおりに進めます。

指示を出す前に、地図撮影用のChrome（9222）を起動しておきます（導入の④）。

デザインや決まった文（タイトル・キーワード選定の考え方・最後のお願い）は変えない。変えたいときは自分で直さず、上長に相談する。
5
確認 確認して送る
送る前のチェック
  • 店舗名・開始日が正しい
  • 項目の順番と番号が合っている（開始日は番号なし）
  • 地図の円が店舗の位置にあり、半径が入力どおり
  • 黄色の「ご確認ください」は、確認したい項目にだけ付いている
  • リンク先・ご連絡シートのリンクが開ける
  • スマホでも文字が読める
  • Aloomに保存した（表示名は「〇〇 広告設定案」）。お客様にはAloomのURLを送る

チェックが済んだら、AloomのURLをメールまたはLINEで、前日までに送ります。Aloomへの保存は「〇〇の設定案をAloomに保存して」とClaudeに頼めば行ってくれます。メールで送るときの文面は、ヒアリングスクリプトの「事前準備」にあります。

6
ヒアリング ヒアリングで使う

電話では、お客様と同じ設定案を開いて、番号順に確認します。ヒアリングスクリプトの各項目に、対応する設定案の番号を付けています。

  • 話すときは「1番のリンク先ですが〜」と番号で場所を伝える
  • 黄色の「ご確認ください」の項目は必ずその場で決める
  • 電話のあと、変わった内容を設定案に反映し、Aloomに保存し直す。Aloomの版は自動で更新されないので、新しいURLをお客様に送り直す
